# MagicDecks Repository Guide

This guide helps Claude Code understand the structure and workflow of the MagicDecks project.

## Repository Purpose

This project manages a Magic: The Gathering card collection, matches cards to preconstructed decks, and generates AI-powered Commander deck lists from the collection.

## Directory Structure

```
MagicDecks/
├── Precons/                      # Deck lists for preconstructed decks owned
│   ├── Commander Precons/        # Commander format precon decks
│   │   └── *.txt                 # One file per Commander precon
│   └── *.txt                     # Non-Commander precons and Secret Lair drops (e.g. Foundations Beginner Box, Sonic Secret Lair)
├── Custom Decks/                 # AI-generated or custom deck lists
│   └── *.md                      # Generated Commander decks (markdown format)
├── scripts/cache/                        # Cache files for Scryfall data
│   ├── cards_cache.json          # Scryfall API response cache
│   └── scryfall_raw_responses.md # Raw JSON responses from Scryfall API
├── scripts/
│   ├── generate_cards_md.py      # Main script to process collection
│   └── README.md                 # Script documentation
├── .claude/
│   ├── REPO_GUIDE.md             # This guide
│   └── skills/
│       ├── generate-deck.md      # AI deck generator skill
│       └── README.md             # Skills documentation
├── moxfield_collections/         # Historical Moxfield collection snapshots (dated CSVs) — check here to see what changed between collection updates
├── moxfield_latest.csv           # Raw card collection (Moxfield export)
├── moxfield_cards.md             # Readable card list with precon assignments
└── card_details.md               # Card details from Scryfall (mana, type, text, etc.)
```

## File Descriptions

### Source Files

- **moxfield_latest.csv**: Raw CSV export from Moxfield containing the user's card collection. This is the primary source of truth for what cards are owned.
  - Columns: Name, Edition, Count, etc.
  - Updated manually by exporting from Moxfield

- **Precons/Commander Precons/*.txt**: Deck lists for Commander format preconstructed decks
  - Format: One card per line, optional quantity prefix (e.g., "2 Island")
  - Optional first line ending with ":" to set deck title
  - Supports alt names in square brackets: `Card Name [Alt Name]`
- **Precons/*.txt**: Non-Commander precons and Secret Lair drops (e.g. Foundations Beginner Box, Sonic Secret Lair packs)

### Generated Files

- **moxfield_cards.md**: Human-readable card list generated by `generate_cards_md.py`
  - Table format with columns: Name, Edition, Count, Precon, Duplicate
  - Shows which cards belong to which precons
  - Includes per-precon reports (missing cards, extras, heuristic matches)
  - Generated from `moxfield_latest.csv` and `Precons/`

- **card_details.md**: Detailed card information fetched from Scryfall
  - Table with: Name, URI, Scryfall URI, mana cost (plain English), type, colors, oracle text, power/toughness
  - Includes per-card sections with constructed URLs and tried URLs
  - Generated by `generate_cards_md.py` via Scryfall API

### Cache Files

- **scripts/cache/scryfall_raw_responses.md**: Complete raw JSON responses from Scryfall API
  - One section per card with full JSON data
  - Includes attempted URLs and success/failure status
  - Used for debugging and complete card data access

- **scripts/cache/cards_cache.json**: Local cache of all Scryfall API responses
  - Prevents redundant API calls
  - Persists between script runs
  - Format: `{card_name: {data: {...}, urls: [...]}}`

## Workflow

### 1. Update Collection
1. Export collection from Moxfield as CSV
2. Save as `moxfield_latest.csv` in repo root

### 2. Generate Card Data
Run the processing script from repo root:
```bash
python scripts/generate_cards_md.py \
  --csv moxfield_latest.csv \
  --precons Precons \
  --out moxfield_cards.md \
  --card-details card_details.md \
  --cache scripts/cache/cards_cache.json
```

This will:
- Parse the CSV and precon files
- Match cards to precons (exact, alt-name, fuzzy matching)
- Generate `moxfield_cards.md` with readable card table
- Fetch card details from Scryfall API (incremental, skips cached)
- Generate `card_details.md` with detailed card info
- Write raw responses to `scripts/cache/scryfall_raw_responses.md`
- Update cache in `scripts/cache/cards_cache.json`

### 3. Generate Decks (AI Skill)
Use the `/generate-deck` skill in Claude Code:
```
/generate-deck elf tribal in green and white
```

This will:
- Read available cards from `moxfield_latest.csv`
- Read card details from `card_details.md`
- Generate a 100-card Commander deck using only owned cards
- Save to `Custom Decks/[deck-name].md` (draft version)

**Versioning workflow**:
- Initial generation creates a draft: `[Deck Name].md`
- Iterate by requesting changes (draft is overwritten)
- Lock when satisfied: "Lock this in" → renamed to `[Deck Name] v1.md`
- Future changes create new drafts, lock as v1.1, v1.2, etc.
- Locked versions are preserved and never overwritten

## Key Data Sources for AI Skills

When building AI features, use these files:

1. **For card availability**: `moxfield_latest.csv` (what cards are owned)
   - Alternative: `moxfield_cards.md` (more readable, includes precon info)

2. **For card details**: `card_details.md` (mana cost, type, colors, oracle text)
   - Has human-readable mana costs (e.g., "1 generic, Blue, Red")
   - Has color identity information
   - Has oracle text with symbols converted to words

3. **For complete Scryfall data**: `scripts/cache/cards_cache.json`
   - Full JSON objects with all Scryfall fields
   - Use when you need fields not in `card_details.md`

## Card Matching Logic

The `generate_cards_md.py` script uses sophisticated matching:

1. **Exact match**: Normalized name match (lowercase, no parens, no special chars)
2. **Alt name match**: Cards can have alternative names in brackets
3. **Fuzzy match**: Uses difflib.SequenceMatcher for similarity
   - Auto-assign threshold: 0.90 (high confidence)
   - Ambiguous threshold: 0.75 (needs review)

## Pull Request Workflow

When pushing changes and creating or updating a PR:

1. **Before creating or updating a PR**, check whether an existing PR for the current branch is already merged:
   - Use `mcp__github__list_pull_requests` or `mcp__github__pull_request_read` to look up open PRs for the branch.
   - If the PR state is `merged` or `closed`, do **not** try to update it — create a **new PR** instead.
   - If no open PR exists for the branch, create a new one.

2. **If a PR is still open**, you may update its title/body with `mcp__github__update_pull_request` to reflect the latest changes.

3. **Always verify the PR target branch** is `main` unless explicitly told otherwise.

## Important Notes

- All generated files (*.md, cache) should be committed to git
- Scryfall API has rate limits - script includes 1-second delays
- Cards already in cache or successfully fetched are skipped on re-runs
- The cache avoids HTTP 429 (rate limit) errors
- UTF-8 encoding is used throughout

## Adding New Features

When creating new AI skills or scripts:
1. Use `moxfield_latest.csv` as the source of truth for owned cards
2. Use `card_details.md` for card details (don't re-fetch from Scryfall)
3. Use `scripts/cache/cards_cache.json` if you need full Scryfall data
4. Save outputs to appropriate directories (Custom Decks for decks, scripts for tools, cache for API responses)
5. Document new skills in `.claude/skills/README.md`
